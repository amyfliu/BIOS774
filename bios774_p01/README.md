# Building an AI Agent for Dimension Reduction and Exploratory Data Analysis

## Overview

Dimension reduction (DR) — from linear methods like PCA to nonlinear
ones like UMAP, t-SNE, and diffusion maps — is a core tool for exploring
high-dimensional data such as single-cell gene expression or biomedical
images, but no single method or preprocessing choice works universally:
the right decision depends on a dataset's sparsity, scale heterogeneity,
and expected structure, and has traditionally required a human analyst's
judgment. This project investigates replacing that judgment with an AI
agent: a large language model that inspects each dataset, selects and
justifies its own preprocessing and DR method choices based on the
evidence it observes, runs and evaluates the resulting embedding, and
reports its findings. The following DR methods are available: PCA,
Kernel PCA, MDS, Isomap, LLE, Laplacian Eigenmaps, Diffusion Maps,
t-SNE, and UMAP. The system architecture is summarized in the following
figure.

```

├── requirements.txt               # required packages
├── AGENTS.md                      # top-level task instructions for the agent
├── .agents/
```

## Setup

Please install the required packages (tip: a virtual environment can be
created to avoid package inconsistencies).

```         
pip install -r requirements.txt
```

### 1. Prepare the datasets (run locally — needs normal internet access)

The datasets used for this project are not included because of size
limits. Please run the following script from the project root to get a
local copy of the data via `prepare.py`:

```         
cd data/pbmc3k && python prepare.py && cd ../..
cd data/pathmnist && python prepare.py && cd ../..
```

Each writes `prepared.npz` + `DATA.md` into its own folder. These are
the ONLY dataset-specific scripts in the project; everything else
(`tools/*.py`) is generic.

### 2. Run the agent

This project is designed to be driven by **Claude Code**, reading
`AGENTS.md` at the project root plus the skills in `.agents/skills/`.
After constructing the datasets in step 1) above, run Claude from the
repository root and ask it to analyze the dataset of interest and create
the report:

```         
claude
> Follow AGENTS.md. Process both datasets under data/ and produce
> reports/generated_report_1.md and reports/generated_report_2.md.
```

The agent should, per dataset: inspect it, decide preprocessing, decide
which DR method(s) to run, run and evaluate them, then write the report.
You should not need to specify preprocessing/method choices yourself.

### 3. Examine the reports

The agent's workflow (`AGENTS.md`) produces
`reports/generated_report_1.md` and `reports/generated_report_2.md`,
each with a matching `.pdf` exported alongside it by default (see
`AGENTS.md`'s "PDF export" section for how). Note that a missing PDF
converter on the machine won't block the task — the `.md` is always the
primary deliverable.

`reports/report.md` / `report.pdf` is a separate write-up — not produced
by the autonomous `AGENTS.md` workflow, but assembled directly for this
project — documenting the agent system itself (architecture,
decision-making, tools/models used, dataset evaluation results,
strengths and limitations), including a system architecture diagram
(`reports/architecture.png`, editable source in
`reports/architecture_tikz.tex`).
